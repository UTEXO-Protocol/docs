Utexo does not expose one global API contract. The Mint service, RGB Node, RGB Lightning Node, and Utexo Cloud have separate endpoints, authentication models, and release lifecycles.

<Warning>
  Select the reference for the product you are calling. Do not use a generic or sample OpenAPI document as a contract for Utexo services.
</Warning>

For the RGB Lightning Node, the hosted interactive reference is also available at [utexo-protocol.github.io/rgb-lightning-node](https://utexo-protocol.github.io/rgb-lightning-node).

## Source-of-Truth Rules

- Treat the specification owned by the service repository as authoritative for paths and schemas.
- Keep generated reference pages scoped to one product specification.
- Vendor a specification into this documentation repository only when its publication owner and update process are defined.
- Do not expose a private repository URL as a public documentation dependency.
- Do not document authentication, rate limits, retries, idempotency, or webhook guarantees unless the corresponding implementation is confirmed.

## Known Publication Gap

The `work-in-progress` branch does not contain `api-reference/openapi.json` and does not configure an `openapi` navigation source in `docs.json`. A Plant Store document served from that path is therefore not an API contract committed in this branch.

Removing that sample response requires checking the Mintlify project or deployment configuration that supplies the route. This page prevents the sample from being presented as the API entry point, but the platform-level route must still be removed or redirected before publication.

<Info>
  When a public Mint OpenAPI artifact and synchronization owner are available, add it as a separate Mint specification. Do not merge it with the RGB Lightning Node schema into a synthetic global contract.
</Info>
