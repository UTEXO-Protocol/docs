## Request a quote

1. [List networks and tokens](/product-suite/swap/api/networks-and-tokens) with your affiliate API key.
2. Request a [quote](/product-suite/swap/api/quotes) for the user's token pair and amount.
3. Check the returned amounts, expiry, fees, `swap_type`, and `deposit_type`.
4. Create an [intent](/product-suite/swap/api/intents/creation) with the quote ID and the user's addresses before the quote expires.

For EVM and Tron source tokens, grant Permit2 the required token allowance when the intent uses `permit2`. See [Approve for Permit2](/product-suite/swap/on-chain-helpers/approve-for-permit2).

## Fund the intent

Read `approval_mechanism` from the intent response, then follow the matching procedure:

- For `permit2`, sign with the user's [EVM wallet](/product-suite/swap/api/intents/approvals/evm) or [Tron wallet](/product-suite/swap/api/intents/approvals/tron). Submit the signature as a `permit2` approval.
- For `htlc`, sign the listed [Bitcoin PSBT inputs](/product-suite/swap/api/intents/approvals/bitcoin). Submit the PSBT as a `psbt` approval.
- For `cosign`, sign the returned [Solana transaction](/product-suite/swap/api/intents/approvals/solana). Submit the transaction as a `cosign` approval.
- For `broadcast`, sign and broadcast the returned transaction. For RGB, [pay the returned invoice](/product-suite/swap/api/intents/approvals/rgb). Report the transaction hash through the [user deposit endpoint](/product-suite/swap/api/intents/deposits).

## Track settlement

Poll `GET /affiliate/v1/intents/{intent_id}/status` for the [intent status](/product-suite/swap/api/intents/status). If the intent is declined, read `decline_details`.

Use `GET /affiliate/v1/swaps/intents/{intent_id}` for transaction hashes and amounts. Use [swap history](/product-suite/swap/api/swap-history) to list swaps by wallet or retail user ID.
