An intent binds a quote to the user's source, destination, and refund addresses. The quote also supplies the source amount, destination bounds, and selected resolver.

## Funding flows

The affiliate configuration selects the permit or user-broadcast flow. The intent response identifies the flow through `approval_mechanism`.

- In the permit flow, the user signs a Permit2 message, Bitcoin PSBT, or Solana transaction. The client submits an approval, and the resolver broadcasts the transaction.
- In the user-broadcast flow, the user signs and broadcasts the transaction. For RGB, the user pays the returned witness invoice instead. The client reports the transaction hash.

RGB sources always use the user-broadcast flow, regardless of the affiliate configuration.

## Lifecycle

[Intent creation](/product-suite/swap/api/intents/creation) returns either [approval data](/product-suite/swap/api/intents/approvals) or [user deposit data](/product-suite/swap/api/intents/deposits). Once the source-chain funds are available, the resolver fulfills the swap. [Intent status](/product-suite/swap/api/intents/status) combines the intent state with its execution state.
