```http
POST /affiliate/v1/intents
```

An intent uses a quote owned by the authenticated affiliate. A quote can create only one intent.

## Request

```json
{
	"quote_id": "fe5601fb-60f2-4cb0-8a67-c55bd3640411",
	"user_source_address": "0x1111111111111111111111111111111111111111",
	"user_destination_address": "0x2222222222222222222222222222222222222222",
	"refund_address": "0x1111111111111111111111111111111111111111",
	"user_source_public_key": null,
	"referrer_id": null
}
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `quote_id` | string | Yes | UUID from the [quote response](/product-suite/swap/api/quotes). |
| `user_source_address` | string | Yes | Address that supplies the source tokens. |
| `user_destination_address` | string | Yes | Address on the destination network that receives the output tokens. |
| `refund_address` | string | Yes | Address on the source network that receives a refund. |
| `user_source_public_key` | string | For Bitcoin | Public key for a Bitcoin source, including [RGB USDT](/product-suite/swap/api/intents/approvals/rgb). Solana uses `user_source_address` as the public key. |
| `referrer_id` | string | No | Identifier available as a swap-history filter. |

`retail_user_id` belongs to the quote request. Intent creation copies that identifier from the quote.

## Response

The response uses these common fields:

| Field | Type | Description |
| --- | --- | --- |
| `intent_id` | string | Intent UUID. |
| `deadline_secs` | integer | Intent deadline as a Unix timestamp in seconds. |
| `secret_hash` | string | Hex-encoded secret hash. Bitcoin uses double SHA-256. EVM, Tron, and Solana use Keccak-256. |
| `approval_mechanism` | string | Funding flow selected for this intent. |
| `params_to_sign` | object | Approval data, or an empty object for `broadcast`. |
| `deposit_tx_data` | object or null | Transaction or invoice data for the user-broadcast flow. |

The affiliate's configuration selects the funding flow. RGB sources always use `broadcast`. The request does not select the flow.

| `approval_mechanism` | Source | Next action |
| --- | --- | --- |
| `permit2` | EVM or Tron | Sign the Permit2 message and [submit an approval](/product-suite/swap/api/intents/approvals). |
| `htlc` | Bitcoin | Sign the listed PSBT inputs and submit a `psbt` approval. |
| `cosign` | Solana | Sign the versioned transaction and submit a `cosign` approval. |
| `broadcast` | Depends on affiliate configuration. Required for RGB sources. | Sign and broadcast the returned transaction, or pay the RGB invoice. [Report the transaction hash](/product-suite/swap/api/intents/deposits). |

### Permit2

For `permit2`, `params_to_sign` contains these fields:

| Field | Description |
| --- | --- |
| `escrow_contract_address` | Spender in the Permit2 message. |
| `permit2_contract_address` | Contract that verifies the Permit2 approval. |
| `resolver_deposit_address` | Resolver address bound into the witness. |
| `nonce` | Nonce for the Permit2 message. |
| `additional_data.domain` | Domain with `name`, `version`, `chainId`, and `verifyingContract`. |
| `additional_data.types` | Typed-data definitions, including `PermitWitnessTransferFrom` and the selected witness type. |
| `additional_data.witness` | Witness object. Its integer fields use hex strings, including integers in nested structs. |
| `additional_data.witness_type_string` | Witness type suffix used in the Permit2 hash. |
| `additional_data.witness_hash` | Hex-encoded hash of the witness. |

`deposit_tx_data` is `null` in the approval flows. Signing procedures are in [Sign an EVM intent](/product-suite/swap/api/intents/approvals/evm) and [Sign a Tron intent](/product-suite/swap/api/intents/approvals/tron).

<Note>
	The EVM response includes `domain.version: "1"`, but the current Permit2 verifier hashes a domain without `version`. The signing examples omit that field to match verification. Tron returns `version: null`.
</Note>

### Bitcoin approval

For `htlc`, `params_to_sign` contains a Base64-encoded PSBT and the indexes of the user's inputs:

```json
{
	"psbt": "cHNidP8...",
	"inputs": [0, 1]
}
```

### Solana approval

For `cosign`, `params_to_sign.transaction` contains a hex-encoded versioned transaction:

```json
{
	"transaction": "02000..."
}
```

### Broadcast

For `broadcast`, `params_to_sign` is `{}`. `deposit_tx_data` uses a case-sensitive variant name:

| Variant | Fields |
| --- | --- |
| `EvmLike` | `transaction` is hex-encoded contract calldata. `resolver_deposit_address` identifies the resolver, not the transaction target. |
| `Cosign` | `transaction` is a hex-encoded versioned transaction. Also includes `recent_blockhash` and `resolver_deposit_address`. |
| `Psbt` | `bitcoin_psbt`, `inputs_to_sign` |
| `RgbLock` | `witness_invoice` |

`bitcoin_psbt` contains `psbt`, `x_only_public_key`, `refund_control_block`, and `fast_refund_control_block`. The three Taproot metadata fields can be `null`.

An RGB response includes these fields:

```json
{
	"intent_id": "8a2d3f92-2a2b-4e4c-9d8a-3c9f92e4a111",
	"deadline_secs": 1793700000,
	"secret_hash": "0x19875e12d834bc245b834c4c031d4b89c6354fba4575e44dd26f37d367a44926",
	"approval_mechanism": "broadcast",
	"params_to_sign": {},
	"deposit_tx_data": {
		"RgbLock": {
			"witness_invoice": "wvout:..."
		}
	}
}
```
