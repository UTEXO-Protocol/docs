Bitcoin settlement uses Taproot (P2TR) outputs and BIP 174 PSBTs. No smart contract is deployed on Bitcoin.

## HTLC lock output

An escrowed deposit locks funds to a Taproot output with three script leaves. A direct deposit transfers to the resolver instead.

| Leaf | Script |
| --- | --- |
| Resolver withdraw | `OP_HASH256 <secretHash> OP_EQUALVERIFY <resolverPubKey> OP_CHECKSIG` |
| Timelock refund | `<deadline> OP_CLTV OP_DROP <protocolPubKey> OP_CHECKSIG` |
| Fast refund | `<protocolPubKey> OP_CHECKSIG <resolverPubKey> OP_CHECKSIGADD 2 OP_EQUAL` |

- `secretHash` is double SHA-256 of the 32-byte secret.
- The internal key may be a NUMS point or a resolver-selected key. RGB USDT swaps use a NUMS internal key; see [RGB USDT settlement](/product-suite/swap/resolver-integration/rgb-settlement).
- The resolver returns the refund and fast-refund control blocks to Utexo and keeps the withdraw control block internally.

## Deposit transaction

### Intent tagging

Every deposit contains an `OP_RETURN` output that tags the intent:

```text
OP_RETURN <protocolPrefix> <flag> <intentID>
```

### PSBT inputs

| Field | Value |
| --- | --- |
| `WITNESS_UTXO` | Required for every input. |
| Sighash | `SIGHASH_ALL` (`0x01`). |
| `TAP_INTERNAL_KEY` | User's x-only public key. |
| Sequence | `0xFFFFFFFF` (no RBF). |

### Outputs

| Index | Output |
| --- | --- |
| `0` | `OP_RETURN` with `0` sats. |
| `1` | P2TR HTLC lock. The amount is the deposit minus a proportional share of network fees. |

The deposit has at least two outputs. Additional outputs can return change. Utexo verifies the user's total charge and the escrow control blocks.

## Spend paths

### Key-spend path

Used for deposit input signing, fulfillment, and native transfers.

Witness:

```text
[schnorr_signature]
```

### Resolver withdraw (script-path)

Witness:

```text
[schnorr_signature, secret_preimage, tap_script, control_block]
```

### Fast refund (script-path)

Cooperative script-path spend co-signed by the protocol and the resolver. The witness stack is:

```text
[resolver_signature, protocol_signature, tap_script, control_block]
```

### Timelock refund

Script-path refund after `deadline`.

The refund transaction uses `nLockTime = deadline + 1` and this witness stack:

```text
[protocol_signature, tap_script, control_block]
```

## Fees

The resolver supplies the deposit PSBT and chooses its fee rate. The API does not publish a fixed fee rate or a per-input fee table. The returned PSBT determines the user's Bitcoin charge and change.
