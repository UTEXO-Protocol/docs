The Utexo SDK provides non-custodial Bitcoin and RGB wallet operations. **`@utexo/rgb-sdk` exports `UTEXOWallet`, a shared facade over the engine your application creates.** React Native uses `RgbLibRn`; browsers use `RgbLibWeb`. Node.js and Bare integrations use the separate `@utexo/wdk-wallet-rgb` API.

Both current facade engines support **on-chain operations only**, including BFA assets. Lightning is WIP, available only in separate experimental integrations, and not recommended for production.

## Packages

| Package | Role | Runtime |
| --- | --- | --- |
| `@utexo/rgb-sdk` | `UTEXOWallet` facade and the `/webrgb` provider integration | Runs where its engine runs |
| `@utexo/rgb-sdk-rn` | `RgbLibRn`, backed by native rgb-lib | React Native on iOS and Android |
| `@utexo/rgb-sdk-web` | `RgbLibWeb`, backed by rgb-lib WASM | Browser |
| `@utexo/rgb-sdk-core` | Shared wallet contract, types, errors, and key helpers | Platform-independent |
| `@utexo/wdk-wallet-rgb` | WDK manager/account API for on-chain RGB | Node.js and Bare |
| `@utexo/wdk-rgb-lightning` | Experimental Lightning integration | Testing only |

The facade does not bundle or choose an engine. Install the facade, core, and platform engine together, and satisfy their peer dependency requirements. `@utexo/wdk-wallet-rgb` is not yet integrated into the facade; use its manager/account API separately for Node.js and Bare. See [Platform API Differences](/getting-started/quickstart/overview#platform-api-differences) for constructors and send methods by package.

## Create a Wallet

```typescript
import { UTEXOWallet } from '@utexo/rgb-sdk';
import { RgbLibRn } from '@utexo/rgb-sdk-rn';

const wallet = new UTEXOWallet({
  engine: new RgbLibRn(
    {
      network: 'signet',
      storageDirPath,
      indexerUrl: 'ssl://stage.electrs-signet.mint.utexo.com:60602',
      proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
      evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
    },
    mnemonic,
  ),
});
await wallet.init();
```

The application supplies a persistent native directory and securely stored mnemonic. For the browser, pass `new RgbLibWeb({ network, mnemonic, dataDir, ...connectionSettings })` instead. The Web engine requires an HTTP Esplora indexer.

Construction checks the engine contract. `init()` opens local state, and the first network operation connects automatically. The facade owns the session: use `wallet.destroy()` when finished. See the [facade reference](/sdk/rgb-sdk) for lifecycle and engine extensions.

## Core Capabilities

- Bitcoin addresses, balances, UTXO management, and sends
- RGB invoices, on-chain transfers, asset balances, and history
- NIA and IFA issuance through the shared facade API; further schemas depend on the engine
- BFA inventory, transfer, mint verification, and burn capabilities
- Transaction preparation, fee review, and separate PSBT signing and submission
- Encrypted wallet-state backups using each engine's supported storage mechanism

`wallet.capabilities` describes the engine and signing configuration. Both engines expose `wallet.beginEnd` for separate preparation and submission. `wallet.psbt` provides signing and fee estimation when signing keys are available; watch-only wallets use an external signer. See [Transaction Approval](/sdk/rgb-sdk#transaction-approval).

## Key Concepts

### Vanilla vs Colored Balances

`getBtcBalance()` separates vanilla BTC used for fees from colored UTXOs that can carry RGB allocations. Fund the wallet before spending or creating RGB outputs.

### Invoice Types: Blinded vs Witness

`onchainReceive()` creates a witness invoice by default. The sender funds the new receiver output with `witnessData.amountSat`. A blinded invoice uses `witness: false` or `blindReceive()` and needs a prepared RGB UTXO on the receiver.

Both facade engines send with `onchainSend()` and refresh settlement with `refresh()`. WDK uses `sendRgbInvoice()`, a persisted `operationId`, exact string or `bigint` amounts, and `witnessAmountSats` for witness invoices.

### BFA Assets

React Native and Web return BFA assets in `listAssets().bfa`; WDK returns a flat array with `schema: 'Bfa'`. Select the authoritative asset ID rather than only its ticker. Supply EVM validation RPCs for BFA mint locks.

React Native supports burn proof export. Web supports local burns but currently has no consignment export. The WebRGB provider consequently does not advertise `burnAsset` or `getConsignment` over `RgbLibWeb`.

Both engines expose `getReceivedMint()` to read a checked mint's EVM lock terms. React Native also returns its checked asset ID. See [received mint verification](/sdk/rgb-sdk#check-a-received-bfa-mint) before integrating the payment step.

### Backup and Restore

A mnemonic restores keys and Bitcoin, but RGB also requires wallet state. Backups are engine-specific:

| Engine | Backup | Restore |
| --- | --- | --- |
| React Native | `exportBackupToFile()` or `exportBackup()` | `restoreBackupFromFile()` before opening a wallet in a new directory |
| Web | `exportBackup()` or `backupToVss()` | `restoreBackup()` or `restoreFromVss()` after `init()` and before connecting |
| WDK | Application-managed complete wallet directory and operation journals | Reopen the matching state and recover recorded operations |

The earlier RLN backups and wallet directories are not migrated by changing the constructor.

## Networks

Configure the indexer and RGB proxy for the same deployment on both parties. Public signet examples use the staging RGB proxy. React Native uses the Utexo Electrum indexer; Web uses HTTP Esplora. The `utexo` profile on Web and React Native targets hosted Dev infrastructure, separate from public signet.

WDK has its own configuration and profile rules. See [React Native connection settings](/sdk/react-native-sdk#connection-settings), [Web endpoints](/sdk/web-sdk#default-endpoints), and [WDK configuration](/sdk/wdk-wallet-rgb#configuration).

## WebRGB for dApps

Wallet applications expose a provider using `@utexo/rgb-sdk/webrgb`. dApps use `@utexo/webrgb` to request a provider and inspect its advertised methods. The application handles trusted origins, user confirmation, and persistent operation storage. See [WebRGB integration](/sdk/rgb-sdk#webrgb-integration).
