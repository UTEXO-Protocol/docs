The Utexo SDK provides programmatic access to the Utexo execution layer, enabling applications to issue, transfer, and receive RGB assets on Bitcoin without operating nodes, managing channels, or handling protocol-level infrastructure.

It exposes async methods for wallet management, RGB asset operations, and on-chain Bitcoin interactions. RGB ownership proofs are validated client-side.

<Warning>
  **Current SDK packages support on-chain operations only.** Lightning is **work in progress (WIP)**, available only for experimental testing in builds that include it, and **not recommended for production**. Test-network availability does not make Lightning a supported production feature.

  In `@utexo/rgb-sdk-rn`, **Lightning / RLN is disabled on all networks**. The package supports **on-chain operations only**, through rgb-lib.
</Warning>

## SDK Family

The Utexo SDK is available across three application platforms. `@utexo/rgb-sdk` (Node.js) is archived; new Node.js integrations should use **`@utexo/wdk-wallet-rgb`** for on-chain RGB. A separate Wallet Development Kit (WDK) layer is available for builders who need lower-level wallet abstractions:

| Package | Platform | Current scope |
| --- | --- | --- |
| `@utexo/rgb-sdk-web` | Browser / JS/TS | On-chain RGB via WASM; Lightning is WIP, testing-only |
| `@utexo/rgb-sdk-rn` | React Native | On-chain operations only, via rgb-lib |
| `@utexo/wdk-wallet-rgb` | Node.js & Bare | On-chain RGB, BFA transfers, and burns |
| `@utexo/rgb-sdk` | Node.js (archived) | Legacy server-side SDK — do not use for new integrations |

`@utexo/wdk-rgb-lightning` is retained as an experimental Lightning reference for testing only. It is not the recommended Node.js integration path. React Native integrations use `@utexo/rgb-sdk-rn` for on-chain operations only.

The Web and React Native SDKs share types and interfaces from `@utexo/rgb-sdk-core`, but use different backends, constructors, lifecycles, and network defaults. Check the platform reference before reusing code.

This page covers the SDK family. Refer to the platform reference pages for method-level details. The WDK source is available in the [main branch](https://github.com/UTEXO-Protocol/wdk-wallet-rgb/tree/main).

## What the SDK Provides

- **Wallet management** — key generation, derivation, initialisation, backup, and restore using the mechanisms supported by each package; address rotation following HD wallet best practices
- **RGB asset operations** — blinded and witness invoices, asset transfers, and balance queries; issuance where exposed by the selected package
- **On-chain interactions** — deposit address generation, BTC balance queries, on-chain withdrawal
- **UTXO management** — UTXO creation, listing, and state sync

Lightning payments, HODL invoices, Lightning Address, LSP, and async payments (APay) remain **WIP and testing-only** where an experimental backend is available. They are not recommended for production and are disabled in the current React Native package.

## Key Concepts

### Vanilla vs Colored Addresses

The SDK operates two distinct address and key derivation paths:

- **Vanilla** — the standard Bitcoin derivation path. Vanilla outputs hold regular BTC and are used for fee payments, on-chain withdrawals, and funding operations. `getAddress()` returns a vanilla bech32 receive address.
- **Colored** — the RGB-specific derivation path. Colored outputs carry RGB asset allocations anchored to Bitcoin UTXOs. This path is used internally when creating UTXOs for RGB operations.

Balance methods expose the vanilla and colored paths separately. Method names and key-export result shapes vary by package; see the platform reference.

<Note>
  Before issuing or receiving RGB assets, the wallet must have colored UTXOs prepared. Call `createUtxos()` after funding the vanilla address to set up the UTXO structure required for RGB allocations.
</Note>

### Invoice Types: Blinded vs Witness

RGB receive flows support two invoice styles:

- **Blinded invoice** — most common. The receiver creates a blinded endpoint; the sender pays the invoice directly. Use this for standard app-to-app RGB transfers.
- **Witness invoice** — the receiver binds the transfer to witness data. When sending, Web and React Native require `witnessData.amountSat`; the WDK API requires `witnessAmountSats`. Use this when the integration requires witness-bound receive semantics.

On Web and React Native, receive with `onchainReceive({ witness: false })` for blinded or the default witness invoice, then send with `onchainSend()`. On `@utexo/wdk-wallet-rgb`, receive with `blindReceive()` / `witnessReceive()` or `createRgbInvoice({ mode: 'blind' | 'witness', ... })`, then send with `sendRgbInvoice()`. WDK sends require a persistent `operationId` and string or `bigint` amounts.

### Backup and Restore

Back up wallet state after significant changes such as UTXO creation, asset issuance, and transfers. A mnemonic alone does not recover RGB state. Backup APIs are package-specific:

- **React Native** — `createBackup({ backupPath, password })` creates an encrypted file. Restore with `restoreFromBackup({ backupFilePath, password, dataDir })` before `init()`, then supply the original keys and wallet settings. VSS is unavailable on this backend.
- **Web** — use the file or VSS backup methods documented in the [Web reference](/sdk/web-sdk#backup-and-restore).
- **WDK** — preserve the complete wallet directory and operation journals with an application-managed backup process. The SDK exposes operation recovery, but no `createBackup()` or `restoreAccountFromBackup()` API. A seed-only restore is explicitly BTC-only.

An RLN directory or VSS backup cannot be opened by the current React Native on-chain wallet.

### Private Key Export

Where a package exposes private-key export, treat the resulting key material with the same sensitivity as the mnemonic. Check the installed package’s API; key-export helpers are not shared across all SDKs.

## Execution Model

New Node.js integrations use **`@utexo/wdk-wallet-rgb`** for on-chain RGB. Construct `WalletManagerRgb` with the mnemonic and complete staging configuration, then connect the account:

```ts
import WalletManagerRgb from '@utexo/wdk-wallet-rgb';

const manager = new WalletManagerRgb(mnemonic, {
  network: 'signet',
  mode: 'rgb',
  profile: 'staging',
  startupMode: 'offline',
  dataDir: '/absolute/path/to/signet-rgb-wallet',
  indexerUrl: 'ssl://stage.electrs-signet.mint.utexo.com:60602',
  transportEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
  evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
  nativeExecutable: '/absolute/path/to/utexo-rgb-native',
  nativeSha256: verifiedNativeSha256,
  maxFeeSats: 5000n,
  authorize: (review) => requestWalletApproval(review),
});
const account = await manager.getAccount();
await account.connect();
```

`verifiedNativeSha256` and `requestWalletApproval()` are supplied by the application; see [WDK configuration](/sdk/wdk-wallet-rgb#configuration). Await `manager.shutdown()` when finished.

The Web package uses `UTEXOWallet` with `init()` then `unlock()`. React Native uses `new UTEXOWallet({ params, keys })` and `init()`; the wallet connects automatically on the first network operation, or explicitly through `goOnline(params)`. See the platform references for lifecycle details.

Key execution properties:

- All operations are **non-custodial** — the SDK never transmits private keys or mnemonics
- **Web** uses `@utexo/rgb-sdk-web` (WASM); **React Native** uses `@utexo/rgb-sdk-rn`; **Node.js** uses `@utexo/wdk-wallet-rgb`
- **Signing** — WDK derives account keys from the mnemonic passed to its manager; React Native uses its `keys` provider

## Networks

Pass the network identifier supported by the selected package. Web and React Native use `utexo` for their hosted signet profile. The WDK accepts `signet` and isolated `regtest`, not `mainnet` or `utexo`. Its Node.js quickstart keeps public Bitcoin signet with the required Electrum indexer and the Utexo staging proxy.

Indexer and proxy defaults differ by package. Use the [React Native defaults](/sdk/react-native-sdk#connection-settings), [Web defaults](/sdk/web-sdk#default-endpoints), or [WDK configuration](/sdk/wdk-wallet-rgb#configuration). A test network does not enable Lightning in the current React Native build.

<Note>
  Testnet3 (`testnet`) is not recommended: Bitcoin confirmations there can take hours. For hosted signet development, use `utexo` in Web and React Native, or `signet` with the staging profile in the WDK API.
</Note>
