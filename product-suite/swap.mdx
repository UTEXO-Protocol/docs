Utexo Swap connects user swap requests with resolvers that quote and fulfill them. The API coordinates quotes, intent funding, transaction verification, and settlement.

## Swap lifecycle

A client requests a quote for a source token, destination token, and amount. The API selects the quote with the highest minimum destination amount.

The client creates an intent from that quote and supplies the user's source, destination, and refund addresses. The response identifies how to fund the intent. Depending on the affiliate configuration, the user submits a signed approval or broadcasts a transaction. RGB sources use a witness invoice in the broadcast flow.

After the source deposit is confirmed, the resolver delivers the destination tokens. The client tracks the intent through settlement or its refund path.

[Execute a swap](/product-suite/swap/development/user-flow) covers the integration procedure. [Networks and tokens](/product-suite/swap/api/networks-and-tokens) lists assets visible to your affiliate.

## Settlement

The quote's `deposit_type` identifies an `escrowed` or `direct` deposit. The API selects this value. A direct deposit transfers funds to the resolver and does not provide the source-chain escrow protection of an escrowed deposit.

For escrowed swaps, settlement uses these mechanisms:

| Network | Mechanism |
| --- | --- |
| EVM | A dedicated escrow proxy for the swap. |
| Tron | The EVM escrow model on Tron. |
| Solana | A shared token vault with an `EscrowCheck` PDA that records each order. |
| Bitcoin | A Taproot hash time-locked contract, or HTLC. |

Optimized same-chain swaps settle in one atomic transaction. Standard swaps settle through separate source and destination transactions. [Security model](/product-suite/swap/security-model) explains escrow release and refunds.

## Terms

| Term | Definition |
| --- | --- |
| Intent | A quote bound to the user's addresses and funding flow. |
| Resolver | A liquidity provider that quotes and fulfills swaps. |
| RFQ | Request for quote. |
| Permit2 | Token-spending authorization that combines an on-chain allowance with an off-chain signature. |
| PSBT | Partially Signed Bitcoin Transaction. |
| HTLC | Hash time-locked contract, with a secret-based claim and a refund deadline. |
| Lots | Integer amounts in the token's smallest unit. The API encodes these amounts as decimal strings. |
