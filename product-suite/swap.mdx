## Overview

Utexo Swap is an open liquidity layer that connects fragmented liquidity across multiple blockchains. It lets users swap tokens across Ethereum, Solana, Tron, and Bitcoin through a single execution layer and a single REST API.

Resolvers compete to price and fulfill each swap. Utexo coordinates quote discovery, intent validation, execution, and settlement without taking custody of user funds or acting as the swap counterparty.

<Info>
  Use [`GET /affiliate/v1/networks`](/product-suite/swap/api/networks-and-tokens) and [`GET /affiliate/v1/tokens`](/product-suite/swap/api/networks-and-tokens) to discover the networks and tokens available to your integration instead of hardcoding availability.
</Info>

### Key features

- **Cross-chain swaps:** Swap tokens between Ethereum, Solana, Tron, and Bitcoin.
- **Best execution:** Resolvers compete on price through request-for-quote (RFQ) pricing; the API returns the best available quote.
- **Universal access:** Swap any supported token across any supported chain through one integration.
- **Non-custodial:** Users keep control of their assets throughout the swap. Every swap completes in full or reverts through its refund path.

## How a swap works

1. **Quote** — the client requests the best quote for a token pair and amount.
2. **Intent** — the client creates an intent from the quote with the user's source, destination, and refund addresses.
3. **Approval** — the user signs the chain-specific approval returned with the intent, and the client submits it.
4. **Execution** — the winning resolver deposits the user's assets into a per-swap escrow on the source chain and delivers the destination asset to the user.
5. **Status** — the client tracks the intent until it reaches a final status.

See [User Flow](/product-suite/swap/development/user-flow) for the full sequence.

## Settlement

| Network | Settlement mechanism |
| --- | --- |
| Ethereum / EVM | Dedicated escrow smart contract per swap |
| Tron | Same escrow model as EVM |
| Solana | Program-derived escrow account (PDA) per swap |
| Bitcoin | Taproot-based hash time-locked contract (HTLC) |

Each swap uses an isolated settlement mechanism, so funds associated with one swap are never exposed to another. See [Security Model](/product-suite/swap/security-model).

## Glossary

| Term | Definition |
| --- | --- |
| **Intent** | A user's request to perform a swap, created from a quote and attached to it. |
| **Resolver** | A liquidity provider that prices and fulfills swap intents. |
| **RFQ** | Request for quote; the process through which resolvers return competing prices. |
| **Permit2** | An approval mechanism that combines an on-chain token allowance with an off-chain typed-data signature. |
| **PSBT** | Partially Signed Bitcoin Transaction. Used to authorize Bitcoin HTLC deposits. |
| **HTLC** | Hash time-locked contract; an escrow controlled by a hash condition and a timeout. |
| **Lots** | Integer token amounts in the token's smallest unit, as returned by the API (for example `source_amount_lots`). |
