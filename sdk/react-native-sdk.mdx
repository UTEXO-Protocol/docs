`@utexo/rgb-sdk-rn` exports **`RgbLibRn`**, the on-chain RGB and Bitcoin wallet engine for React Native. It uses native rgb-lib bindings on iOS and Android. Wrap it in **`UTEXOWallet` from `@utexo/rgb-sdk`** for the shared wallet API, or use the engine directly.

The package supports **on-chain operations only**. It has no Lightning / RLN backend. Experimental Lightning remains WIP, testing-only, and not recommended for production.

## Requirements and Installation

- React Native with a working iOS or Android native build environment
- A persistent, writable wallet directory
- A Bitcoin indexer and a protocol 1.0 RGB proxy

```bash
npm install @utexo/rgb-sdk@latest @utexo/rgb-sdk-core@latest @utexo/rgb-sdk-rn@latest
npm install react-native-get-random-values buffer
cd ios && pod install
```

Load the polyfills in the app entry file before importing the SDK:

```javascript
import 'react-native-get-random-values';
import { Buffer } from 'buffer';
globalThis.Buffer ??= Buffer;
```

Rebuild the native application after installing or upgrading. Each engine release pins its native rgb-lib bindings. See the [package setup instructions](https://github.com/UTEXO-Protocol/rgb-sdk-rn/blob/dev/Readme.md) for platform build configuration.

## Construction

Create `RgbLibRn(params, keys)`, then pass it to the facade:

```typescript
import { UTEXOWallet } from '@utexo/rgb-sdk';
import { RgbLibRn, type RgbLibRnParams } from '@utexo/rgb-sdk-rn';

const walletParams: RgbLibRnParams = {
  network: 'signet',
  storageDirPath: '/absolute/path/to/signet-wallet',
  indexerUrl: 'ssl://stage.electrs-signet.mint.utexo.com:60602',
  proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
  evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
};

const wallet = new UTEXOWallet({
  engine: new RgbLibRn(walletParams, mnemonic),
});
await wallet.init();
const address = await wallet.getAddress();
```

Load `mnemonic` from secure application storage. For a new wallet, generate keys with `generateKeys(network)` and save the mnemonic before opening it. Each wallet profile needs its own absolute `storageDirPath`.

### Wallet Parameters and Keys

| Field | Description |
| --- | --- |
| `network` | `mainnet`, `testnet`, `testnet4`, `signet`, `utexo`, or `regtest` |
| `storageDirPath` | Absolute persistent directory dedicated to this wallet |
| `witnessVersion` | `taproot` by default; `segwit-v0` is also supported |
| `maxAllocationsPerUtxo` | Maximum RGB allocations per UTXO; default `5` |
| `reuseAddresses` | Reuse the receive address |
| Connection fields | Indexer, proxy, and BFA validation settings used when connecting |

The second engine argument, `keys`, accepts a mnemonic string, a synchronous or asynchronous mnemonic reader, an object with `getMnemonic()`, or account public keys for a watch-only wallet. A failed mnemonic read rejects with `KEYS_UNAVAILABLE`. Inspect `wallet.capabilities.canSignTransactions` before offering a spend.

## Lifecycle

1. `init()` opens local wallet state without connecting to services.
2. The first network operation connects using constructor settings and network defaults. `unlock(params)` or `goOnline(params)` connects explicitly.
3. `shutdown()` closes the session and preserves data. Reopen the same instance with `init()` or `reinit()`.
4. `destroy()` closes the instance permanently. Use a new instance to reopen the wallet.

`initialize()` aliases `init()`, and `dispose()` aliases `destroy()`. `reinit(params)` opens and connects when parameters are supplied. The facade owns the session; call lifecycle methods on `wallet`, not separately on `wallet.engine`.

### Connection Settings

Connection fields can be stored in the constructor or supplied to `goOnline()`:

```typescript
await wallet.goOnline({
  indexerUrl: 'ssl://stage.electrs-signet.mint.utexo.com:60602',
  proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
  evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
});
```

| Setting | Description |
| --- | --- |
| `indexerUrl` | Electrum (`tcp://`, `ssl://`) or Esplora (`http://`, `https://`) |
| `indexer` | Explicit indexer object; also supports bitcoind authentication. Use this or `indexerUrl`, not both |
| `proxyEndpoint` | Protocol 1.0 RGB transport URI |
| `evmRpcUrls` | EVM JSON-RPC URLs keyed by decimal chain ID; required to validate BFA mint locks on that chain |
| `evmMintLockBlocks` | Accepted lock window `{ min, max }` per EVM chain; default `{ min: 1200, max: 28800 }` |
| `proxyAuthKeys` | Proxy endpoint to 32-byte hex authentication key |

| Network | Indexer | RGB proxy |
| --- | --- | --- |
| `mainnet` | `ssl://electrs-01.utexo.com:50002` | `rpcs://rgb-proxy.utexo.com/json-rpc` |
| `utexo` | `https://dev.esplora-01.mint.utexo.com` | `rpcs://dev.rgb-proxy.utexo.com/json-rpc` |
| `signet` | `ssl://stage.electrs-signet.mint.utexo.com:60602` | `rpcs://staging.rgb-proxy.utexo.com/json-rpc` |

Configure these endpoints explicitly when targeting a deployment. The package's `DEFAULT_INDEXER_URLS` and `DEFAULT_TRANSPORT_ENDPOINTS` exports reflect the installed version's defaults. `regtest` requires explicit connection settings. The `utexo` Dev profile and public `signet` use different hosted infrastructure; their funds are not interchangeable.

## Wallet Methods

These methods are available through the facade as well as directly on `RgbLibRn`.

| Group | Methods |
| --- | --- |
| Bitcoin | `getAddress()`, `rotateVanillaAddress()`, `getBtcBalance(options?)`, `listUnspents(options?)`, `sendBtc(params)` |
| UTXOs and fees | `createUtxos({ upTo?, num?, size?, feeRate?, skipSync? })`, `estimateFeeRate(blocks)` |
| Assets | `listAssets(options?)`, `getAssetBalance(assetId)`, `getAssetMetadata(assetId)` |
| Issuance | `issueAssetNia()`, `issueAssetCfa()`, `issueAssetUda()`, `issueAssetIfa()`, `inflate()` |
| Invoices | `onchainReceive(params)`, `blindReceive(params)`, `witnessReceive(params)`, `decodeRGBInvoice({ invoice })` |
| Sending | `onchainSend({ invoice, assetId?, amount?, feeRate?, minConfirmations?, witnessData?, donation?, skipSync? })` |
| History | `listTransfers(assetId?)`, `listTransfersByTxid(txid)`, `listTransactions(options?)`, `listTransactionsByTxid(txid)` |
| Settlement | `refresh(options?)`, `refreshWallet()`, `syncWallet()`, `failTransfers(params)` |
| Maintenance | `drainTo({ address, feeRate? })`, `deleteTransfers(params?)` |

`listAssets()` groups assets into `nia`, `cfa`, `ifa`, `uda`, and `bfa`. Invoice, balance, and BTC amounts use safe JavaScript integers in base units. Fee rates are integer sat/vB. `refresh()` reports changes keyed by batch transfer ID; `refreshWallet()` returns no result. `syncWallet()` synchronizes chain state rather than completing an RGB transfer by itself.

Use `refresh()` and `listTransfers()` in shared facade code. The engine's older aliases such as `refreshTransfers()` and `listOnchainTransfers()` are not forwarded by the facade.

`wallet.beginEnd` exposes separate preparation and submission for RGB sends, BTC sends, UTXO creation, inflation, and burns. `wallet.psbt` provides `signPsbt()` and `estimateFee()` when signing keys are available. Watch-only wallets can use `beginEnd` with an external signer. See [Transaction Approval](/sdk/rgb-sdk#transaction-approval) for approval, cancellation, and recovery with a saved signed PSBT.

## On-chain Transfer Example

The default invoice is a witness invoice, which does not need a free receiver UTXO. The sender funds its witness output with `witnessData.amountSat`. A blinded invoice receives on an existing RGB-capable UTXO; prepare and confirm the receiver's outputs first.

```typescript
const receive = await receiverWallet.onchainReceive({
  witness: false,
  minConfirmations: 1,
  durationSeconds: 3600,
});

const { txid } = await senderWallet.onchainSend({
  invoice: receive.invoice,
  assetId,
  amount: 100,
  feeRate: 2,
  minConfirmations: 1,
});

await senderWallet.refresh();
await receiverWallet.refresh();
```

`senderWallet` and `receiverWallet` are separately initialized wallets on the same network. The sender holds the asset and BTC for fees. Omit `assetId` in the receive request when the receiver has not learned the asset yet. Refresh both wallets and inspect `listTransfers(assetId)` until settlement.

## BFA and Consignments

USDT on Bitcoin from the Utexo Mint uses BFA and appears in `listAssets().bfa`. Select the asset by its expected asset ID, not only by ticker. Configure `evmRpcUrls` for its issuing EVM chain.

| Method | Description |
| --- | --- |
| `getBfaCapabilities()` | Current `{ bfa, burn, consignment }` availability |
| `getReceivedMint(recipientId, { refreshIncoming? }?)` | Read a checked mint, including its asset ID, or `undefined` |
| `burn({ assetId, amount, burnRecipient?, feeRate, minConfirmations })` | Burn exact decimal-string base units |
| `getConsignment(assetId, txid)` | Export a saved consignment as a Base64 string |
| `getConsignmentPath(assetId, txid)` | Get its local file path |

Check capabilities before offering a burn. For bridge BFA burns, `burnRecipient` is the 32-byte commitment to the payout destination, encoded as 64 hex characters without `0x`. It is not the payout address itself. See [Mint and Burn Integration](/mint/mint-burn-integration) for destination encoding and settlement.

`getReceivedMint()` reads local state by default. Set `refreshIncoming: true` to check newly arrived mint consignments without progressing sends or burns. React Native reads `assetId` from the checked consignment; the mint's amount, deadline block, and EVM chain ID are exact decimal strings. See [received mint verification](/sdk/rgb-sdk#check-a-received-bfa-mint) for return fields and pending or failed receives. BFA supply fields are optional.

## Backup and Restore

`exportBackupToFile()` writes an encrypted archive, and `exportBackup()` returns encrypted bytes for application-managed storage. React Native has no VSS backup extension.

```typescript
import { restoreBackupFromFile } from '@utexo/rgb-sdk-rn';

const filePath = '/absolute/path/to/backups/wallet.rgb';
await wallet.exportBackupToFile({ filePath, password });
await wallet.shutdown();

const dataDir = '/absolute/path/to/restored-wallet';
await restoreBackupFromFile({ filePath, password, dataDir });

const restored = new UTEXOWallet({
  engine: new RgbLibRn({ ...walletParams, storageDirPath: dataDir }, mnemonic),
});
await restored.init();
```

Restore into a new, empty directory before opening it. Keep the original mnemonic and wallet settings separately; the archive does not provide the constructor's keys. Store backup files outside wallet storage and retain an off-device copy. Backups are specific to this engine.

`createBackup({ backupPath, password })` and `restoreFromBackup({ backupFilePath, password, dataDir })` remain deprecated engine APIs. The facade forwards `exportBackupToFile()`, not `createBackup()`.

## Migration and Errors

The platform package no longer exports `UTEXOWallet` or RLN signers. Import the facade from `@utexo/rgb-sdk` and replace `new UTEXOWallet({ params, keys })` with `new UTEXOWallet({ engine: new RgbLibRn(params, keys) })`.

Use `isEngineError()` from `@utexo/rgb-sdk` or `@utexo/rgb-sdk-core` to inspect stable error codes. A native/JavaScript version mismatch requires a native rebuild. An engine contract mismatch requires compatible facade, engine, and core packages.

An earlier RLN directory or VSS backup cannot be opened by this engine. Keep its original recovery material and use a separate profile for the on-chain wallet.

## Lightning Status

Lightning channels, payments, LSP, and APay are absent from this engine and the facade's shared API. Changing networks does not enable them. Separate experimental Lightning integrations remain WIP, testing-only, and not recommended for production.
