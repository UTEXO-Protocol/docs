The `@utexo/rgb-sdk-rn` package provides on-chain RGB and Bitcoin wallet operations for iOS and Android through native **rgb-lib** bindings.

<Warning>
  **The current package supports on-chain operations only.** RLN (`RGB_LN`) and Lightning are disabled in this release on every network, including test networks. Lightning remains work in progress (WIP); experimental builds are for testing only and are not recommended for production.

  This is a beta release, so APIs may change. The API examples below follow `1.0.0-beta.39` and its on-chain wallet API.
</Warning>

## What You Can Do

- Issue, receive, transfer, and manage RGB assets (NIA, CFA, IFA, UDA)
- Receive and transfer BFA assets, including USDT on Bitcoin; check burn and consignment capabilities through `getBfaCapabilities()`
- Manage Bitcoin addresses, balances, UTXOs, and on-chain BTC sends
- Track Bitcoin transactions and RGB transfer settlement
- Back up and restore wallet state with encrypted files

Lightning channels, BOLT11 payments, HODL invoices, LSP, APay, virtual channels, and RLN VSS recovery are unavailable in the current package. An exported method or type for these features does not mean that the native backend is enabled.

## Requirements and Installation

- React Native with **New Architecture** enabled
- iOS 16.0 or later
- Android `minSdkVersion` 24, with `arm64-v8a` or `x86_64`
- A persistent, writable wallet directory
- A Bitcoin indexer and an RGB proxy implementing **protocol 1.0**; known networks provide defaults

```bash
npm install @utexo/rgb-sdk-rn
```

The package installs native rgb-lib dependencies during `postinstall`. On iOS, set the application's deployment target to 16.0 or later, then install pods:

```bash
cd ios && pod install
```

Android resolves the pinned `com.utexo:rgb-lib-bfa-android` dependency through Gradle. Rebuild the native application after installing or updating the SDK. The current build does not require an RLN framework, daemon port, or Lightning peer port.

## Primary Class: `UTEXOWallet`

### Construction

Pass one options object containing wallet parameters and keys. Omitting `protocol` selects `RGB_L1`; `protocol: 'RGB_L1'` is also accepted.

```typescript
import {
  UTEXOWallet,
  generateKeys,
  type RgbLibWalletParams,
} from '@utexo/rgb-sdk-rn';

const network = 'utexo';
// First use only: persist this mnemonic in secure storage before init().
// On subsequent launches, load the saved mnemonic instead.
const { mnemonic } = await generateKeys(network);
const walletParams: RgbLibWalletParams = {
  network,
  storageDirPath: '/path/to/wallet-storage',
};

const wallet = new UTEXOWallet({ params: walletParams, keys: mnemonic });
await wallet.init();
const address = await wallet.getAddress(); // available offline
```

`storageDirPath` must be an absolute native filesystem path. Give each wallet profile its own directory.

### `RgbLibWalletParams`

| Field | Type | Description |
| --- | --- | --- |
| `network` | `BitcoinNetwork` | `mainnet`, `testnet`, `testnet4`, `signet`, `utexo`, or `regtest` |
| `storageDirPath` | `string` | Absolute path dedicated to this wallet |
| `witnessVersion` | `'taproot' \| 'segwit-v0'` | Optional witness version; preserve the setting when restoring |
| `maxAllocationsPerUtxo` | `number?` | Maximum RGB allocations per UTXO; default `5` |
| `reuseAddresses` | `boolean?` | Reuse addresses; default `false` |

### Keys

`keys` accepts a mnemonic string, a synchronous or asynchronous mnemonic reader, or an object with `getMnemonic()`. A reader lets the application load the mnemonic from platform-backed secure storage for each new session. An empty or failed read rejects `init()` with `KEYS_UNAVAILABLE`.

Public-key-only configurations create a watch-only wallet. See the [`RgbLibKeys` types](https://github.com/UTEXO-Protocol/rgb-sdk-rn/blob/dev/src/wallet/rgb-lib/key-provider.ts) for supported key providers. `PasswordRLNSigner` and `NativeExternalRLNSigner` belong to the disabled RLN backend and are not used for on-chain wallet initialization.

## Lifecycle

1. Call **`init()`** to open the local wallet.
2. Network operations connect automatically using the configured network defaults. For custom endpoints or `regtest`, call **`goOnline(params)`** before the first network operation.
3. Call **`shutdown()`** to stop the session while preserving wallet data. Reopen the same instance with **`init()`**.
4. Call **`dispose()`** or **`destroy()`** to release the instance permanently. Stored wallet data is preserved; create a new instance to reopen it.

`initialize()` aliases `init()`. `reinit(params)` opens the wallet and connects with the supplied parameters; without parameters it only opens the local session. A separate RLN-style `unlock()` step is not required. `unlock(params)` remains available as a connection alias.

```typescript
await wallet.syncWallet(); // connects automatically

await wallet.shutdown();
await wallet.init();
await wallet.refreshTransfers(); // reconnects automatically

// When finished with this instance:
await wallet.dispose();
```

### Connection Settings

To override defaults, call `goOnline()` after `init()` and before network operations:

```typescript
await wallet.goOnline({
  indexer: { type: 'electrum', url: indexerUrl }, // tcp:// or ssl://
  proxyEndpoint, // a protocol 1.0 RGB proxy on the same network
});
```

`RgbLibUnlockParams` also supports Esplora or bitcoind indexers, `evmRpcUrls` for BFA validation, and `proxyAuthKeys` for authenticated proxies. Supply custom settings again after `shutdown()` and `init()`.

| Network | Indexer | RGB proxy |
| --- | --- | --- |
| `mainnet` | `ssl://electrs-01.utexo.com:50002` | `rpcs://rgb-proxy.utexo.com/json-rpc` |
| `utexo` | `https://dev.esplora-01.mint.utexo.com` | `rpcs://dev.rgb-proxy.utexo.com/json-rpc` |
| `signet` | `ssl://stage.electrs-signet.mint.utexo.com:60602` | `rpcs://staging.rgb-proxy.utexo.com/json-rpc` |

Use `goOnline()` to configure these endpoints explicitly. The package's `DEFAULT_INDEXER_URLS` and `DEFAULT_TRANSPORT_ENDPOINTS` exports reflect the defaults in the installed version. Defaults differ between SDK packages; `utexo` and `signet` select different hosted endpoint profiles.

## Wallet Methods

### Balances, Addresses, and UTXOs

| Method | Description |
| --- | --- |
| `getAddress()` / `rotateVanillaAddress()` | Get the current BTC deposit address / derive a fresh address |
| `getBtcBalance({ skipSync? }?)` | Vanilla and colored BTC balances |
| `getNetwork()` | Configured network |
| `createUtxos({ upTo?, num?, size?, feeRate?, skipSync? })` | Prepare UTXOs for RGB allocations; `size` is in satoshis and `feeRate` is an integer in sat/vB |
| `listUnspents({ skipSync? }?)` | Unspent outputs and RGB allocations |
| `sendBtc({ address, amount, feeRate, skipSync? })` | Send BTC on-chain |
| `estimateFeeRate(blocks)` | Estimate an integer sat/vB fee rate |

### RGB Assets and Transfers

| Method | Description |
| --- | --- |
| `listAssets({ filterAssetSchemas? }?)` | Assets grouped into `nia`, `cfa`, `ifa`, `uda`, and `bfa` |
| `getAssetMetadata(assetId)` / `getAssetBalance(assetId)` | Asset metadata / balance |
| `issueAssetNia({ ticker, name, precision, amounts })` | Issue a non-inflationary asset |
| `issueAssetCfa(params)` / `issueAssetIfa(params)` / `issueAssetUda(params)` | Issue other supported asset schemas |
| `inflate({ assetId, inflationAmounts, feeRate?, minConfirmations? })` | Inflate an IFA asset |
| `onchainReceive({ assetId?, amount?, assignmentKind?, durationSeconds?, minConfirmations?, witness? })` | Create an RGB invoice; witness by default, blinded with `witness: false` |
| `blindReceive(params)` / `witnessReceive(params)` | Explicit blinded / witness receive methods |
| `decodeRGBInvoice({ invoice })` | Decode an RGB invoice |
| `onchainSend({ invoice, assetId?, amount?, donation?, feeRate?, minConfirmations?, witnessData? })` | Send RGB on-chain; `assetId` and `amount` can come from the invoice |
| `listTransfers(assetId?)` / `listOnchainTransfers(assetId?)` | RGB transfer history |
| `listTransfersByTxid(txid)` | RGB transfers for a Bitcoin transaction |
| `listTransactions({ skipSync? }?)` | On-chain transaction history |
| `syncWallet()` | Sync Bitcoin and UTXO state |
| `refreshWallet()` | Advance RGB transfers; returns `Promise<void>` |
| `refreshTransfers(skipSync?)` | Detailed refresh result keyed by batch transfer ID |

Amounts in invoice and balance APIs must fit safe JavaScript integers. One displayed asset unit equals `10 ** precision` base units. The default on-chain send fee rate is `2` sat/vB; `onchainSend()` always syncs even if `skipSync` is supplied.

### BFA and Consignments

USDT on Bitcoin from the Utexo Mint uses the BFA schema and appears in `listAssets().bfa`.

| Method | Description |
| --- | --- |
| `getBfaCapabilities()` | Report `{ bfa, burn, consignment }` for the native build and available keys |
| `burn({ assetId, amount, burnRecipient?, feeRate, minConfirmations })` | Burn asset units; returns `{ txid, batchTransferIdx }` |
| `getConsignment(assetId, txid)` | Export a saved consignment as Base64 |
| `getConsignmentPath(assetId, txid)` | Get its local proof path |

Check capabilities before offering burn. Burn amounts are positive decimal u64 strings; BFA requires a 32-byte hex `burnRecipient` without `0x`. See [Mint and Burn Integration](/mint/mint-burn-integration) for the bridge flow.

## On-chain Transfer Example

Fund both wallets with BTC and prepare RGB UTXOs before receiving. The sender must already hold the asset. Use a blinded invoice for this example:

```typescript
await receiverWallet.syncWallet();
await receiverWallet.createUtxos({ upTo: true, num: 4, feeRate: 2 });

// Omit assetId/amount when the receiver has not received this asset before.
const receive = await receiverWallet.onchainReceive({
  witness: false,
  minConfirmations: 1,
  durationSeconds: 3600,
});

const { txid } = await senderWallet.onchainSend({
  invoice: receive.invoice,
  assetId,
  amount: 100, // base units
  feeRate: 2,
  minConfirmations: 1,
});

await senderWallet.refreshTransfers();
await receiverWallet.refreshTransfers();
```

Refresh both wallets as the transfer progresses and inspect `listTransfers(assetId)` until settlement. A single refresh does not guarantee that the required Bitcoin confirmations have arrived. For witness invoices, supply `witnessData` with at least `amountSat` when sending.

## Backup and Restore

The on-chain wallet uses encrypted file backups. **VSS and `backupNow()` belong to RLN and are unavailable for this backend.**

```typescript
import { restoreFromBackup } from '@utexo/rgb-sdk-rn';

// Use a new file in an existing directory outside wallet storage.
const backupPath = '/path/to/backups/wallet.rgb';
await wallet.createBackup({ backupPath, password });
await wallet.shutdown(); // stop the original before switching to the restored copy

const dataDir = '/path/to/restored-storage';
await restoreFromBackup({
  backupFilePath: backupPath,
  password,
  dataDir,
});

const restored = new UTEXOWallet({
  params: { ...walletParams, storageDirPath: dataDir },
  keys: mnemonic, // the original wallet's mnemonic
});
await restored.init();
```

Restore before `init()` into a new, empty directory. Paths must be absolute native paths, not `file://` URIs; the encryption password must be nonempty. Keep the original mnemonic and wallet settings (`network`, `witnessVersion`, `maxAllocationsPerUtxo`) separately. The archive and password do not supply the constructor's keys. Update backups after wallet changes and arrange off-device storage in the application.

## Migrating from the Previous RLN Examples

The old `new UTEXOWallet(nodeParams, signer)` constructor selects `RGB_LN`. Replace it with `new UTEXOWallet({ params, keys })` for the current on-chain backend. Remove RLN signer, daemon/peer port, channel, LSP, APay, and VSS setup from the on-chain flow.

Use a separate mnemonic and storage directory for the new on-chain wallet profile. An existing RLN directory or VSS backup is not a backup for the current on-chain wallet, and changing the constructor does not migrate its assets or channel state. Preserve the previous profile and its recovery material.

## Lightning Status

Lightning is **WIP and testing-only**, and is **not recommended for production**. It is **disabled in the current `@utexo/rgb-sdk-rn` package on all networks**. Selecting `RGB_LN`, switching to signet, or calling an exported Lightning method does not enable the missing native backend. Earlier RLN, channel, payment, and LSP examples require a separate experimental build and are not part of this integration guide.
