`@utexo/rgb-sdk-web` exports **`RgbLibWeb`**, an on-chain wallet engine backed by **`@utexo/rgb-lib-wasm`**. It stores wallet state in IndexedDB and supports Bitcoin, RGB transfers, and BFA assets. Use it directly or wrap it in **`UTEXOWallet` from `@utexo/rgb-sdk`**.

The current engine has **no Lightning / RLN backend**. The former RLN constructor, password-based startup, channel APIs, and Lightning gateway settings do not apply.

## Installation and Bundler Setup

Use a browser with WebAssembly and IndexedDB, an ESM bundler, an HTTP Esplora indexer, and a protocol 1.0 RGB proxy.

```bash
npm install @utexo/rgb-sdk@latest @utexo/rgb-sdk-core@latest @utexo/rgb-sdk-web@latest
```

The WASM loader resolves `rgb_lib_wasm_bindings_bg.wasm` relative to its JavaScript module. The bundler must serve that asset, or the application must provide `wasmUrl`.

For Vite, exclude both engine packages from dependency pre-bundling:

```typescript
import { defineConfig } from 'vite';

export default defineConfig({
  optimizeDeps: {
    exclude: ['@utexo/rgb-sdk-web', '@utexo/rgb-lib-wasm'],
  },
});
```

The package does not require a separate WASM plugin for the documented Vite setup. If using another bundler, verify that the `.wasm` asset is emitted and reachable in the production build.

## Wallet Initialization

```typescript
import { UTEXOWallet } from '@utexo/rgb-sdk';
import { RgbLibWeb } from '@utexo/rgb-sdk-web';

const wallet = new UTEXOWallet({
  engine: new RgbLibWeb({
    network: 'signet',
    mnemonic,
    dataDir: 'my-signet-wallet',
    indexerUrl: 'https://mempool.space/signet/api',
    proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
    evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
  }),
});

await wallet.init();
const address = await wallet.getAddress();
```

Load `mnemonic` from secure application storage. Generate and save keys only when creating a new wallet. The facade owns the engine session; use its lifecycle methods throughout.

The engine can also run directly as `await RgbLibWeb.create(config)`. That helper constructs and initializes the engine; it is not a static factory on the facade.

### Configuration

| Field | Description |
| --- | --- |
| `network` | `mainnet`, `testnet`, `testnet4`, `signet`, `utexo`, or `regtest` |
| `mnemonic` / `keys` | Exactly one: a mnemonic or a key provider, including watch-only public keys |
| `dataDir` | IndexedDB key prefix; default `':memory:'` is still persisted, not an in-memory-only wallet |
| `reuseAddresses` | Reuse a pinned receive address |
| `maxAllocationsPerUtxo` | Maximum allocations per UTXO; default `5` |
| `indexerUrl` / `indexer` | Esplora URL or `{ type: 'esplora', url }`; use one form |
| `proxyEndpoint` | Protocol 1.0 RGB proxy URI |
| `evmRpcUrls` | EVM validation RPC URLs keyed by decimal chain ID for BFA mint locks |
| `evmMintLockBlocks` | Accepted `{ min, max }` lock window per EVM chain; default `{ min: 1200, max: 28800 }` |
| `proxyAuthKeys` | Proxy endpoint to 32-byte hex authentication key |
| `wasmUrl` / `runtime` | Custom WASM asset URL or an initialized runtime; use at most one |
| `vssUrl` | VSS server; `null` disables VSS |
| `vss` | Explicit VSS identity; use this or `vssUrl` |

### Lifecycle

1. Construction validates configuration and stores it.
2. `init()` loads WASM and opens the local IndexedDB wallet.
3. The first operation that needs the network connects automatically. `unlock(params)` or `goOnline(params)` connects explicitly.
4. `destroy()` closes the wallet and preserves its stored state. Reopen with a new engine and the same keys, network, and `dataDir`.

Restore backups **after `init()` and before any connection or online operation**. `RgbLibWeb` has no `shutdown()` or `reinit()` extension. The facade's `initialize()` and `dispose()` alias `init()` and `destroy()`.

### Default Endpoints

Browser wallets require Esplora over HTTP(S). They cannot use an Electrum `ssl://` endpoint directly.

| Network | Configuration |
| --- | --- |
| `signet` | Set `indexerUrl: 'https://mempool.space/signet/api'` and `proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc'` explicitly |
| `utexo` | Hosted Dev defaults: `https://dev.esplora-01.mint.utexo.com` and `rpcs://dev.rgb-proxy.utexo.com/json-rpc` |
| `mainnet` | Override the engine's Electrum default with a compatible mainnet Esplora URL |
| `regtest` | Configure the local Esplora and RGB proxy explicitly |

The `utexo` Dev profile and public signet use different hosted infrastructure. Configure `evmRpcUrls` for the chain that issued the BFA asset. Services called by the browser must permit the application's origin through CORS.

## On-chain Methods

| Group | Methods |
| --- | --- |
| Bitcoin | `getAddress()`, `getBtcBalance(options?)`, `listUnspents(options?)`, `sendBtc(params)` |
| UTXOs and fees | `createUtxos({ upTo?, num?, size?, feeRate?, skipSync? })`, `estimateFeeRate(blocks)` |
| Assets | `listAssets(options?)`, `getAssetBalance(assetId)` |
| Issuance | `issueAssetNia(params)`, `issueAssetIfa(params)`, `inflate(params)` |
| Invoices | `onchainReceive(params)`, `blindReceive(params)`, `witnessReceive(params)`, `decodeRGBInvoice({ invoice })` |
| Sending | `onchainSend({ invoice, assetId?, amount?, feeRate?, minConfirmations?, witnessData?, donation?, skipSync? })` |
| History | `listTransfers(assetId?)`, `listTransactions(options?)` |
| Settlement | `refresh(options?)`, `refreshWallet()`, `syncWallet()`, `failTransfers(params)` |

Amounts in balances and invoices use safe integer base units; fee rates use integer sat/vB. `listAssets()` groups assets by schema, including `bfa`. Select USDT on Bitcoin by its expected BFA asset ID rather than its ticker alone.

`refresh()` returns per-transfer outcomes keyed by batch transfer ID. A successful send or one refresh does not establish settlement: refresh both wallets and inspect `listTransfers(assetId)` until the transfer is `Settled` or `Failed`.

`wallet.beginEnd` exposes separate preparation and submission for RGB sends, BTC sends, UTXO creation, inflation, and burns. `wallet.psbt` provides `signPsbt()` and `estimateFee()` when signing keys are available. Watch-only wallets can use `beginEnd` with an external signer. See [Transaction Approval](/sdk/rgb-sdk#transaction-approval) for approval, cancellation, and recovery with a saved signed PSBT.

### Blinded and Witness Invoices

`onchainReceive()` creates a witness invoice by default. The receiver needs no free UTXO; the sender pays for the new output with `witnessData.amountSat`.

```typescript
const receive = await receiverWallet.onchainReceive({
  minConfirmations: 1,
  durationSeconds: 3600,
});

const result = await senderWallet.onchainSend({
  invoice: receive.invoice,
  assetId,
  amount: 100,
  feeRate: 2,
  minConfirmations: 1,
  witnessData: { amountSat: 1000 },
});
```

`senderWallet` and `receiverWallet` are separate initialized wallets on the same network. The sender holds the asset and BTC for fees. A blinded invoice uses `witness: false` or `blindReceive()` and requires a prepared, confirmed RGB UTXO on the receiver. Omit `witnessData` when sending to it.

## BFA Mints and Burns

`getReceivedMint(recipientId, { refreshIncoming: true })` checks pending incoming mint consignments and returns the mint's EVM lock terms, or `undefined` if no checked mint is available. It does not progress outgoing sends or burns. Without `refreshIncoming`, it reads local state. Integer fields are exact decimal strings. The current Web engine does not return the checked consignment's `assetId`; WebRGB mint verification therefore requires an invoice that names the asset. See [received mint verification](/sdk/rgb-sdk#check-a-received-bfa-mint). BFA supply fields are optional.

`getBfaCapabilities()` reports whether the wallet can burn and export proofs. `burn({ assetId, amount, burnRecipient?, feeRate, minConfirmations })` uses a decimal-string amount. A bridge BFA burn commits to the payout destination in `burnRecipient`; see [Mint and Burn Integration](/mint/mint-burn-integration).

The current WASM engine can burn but **cannot export consignments**. `getConsignment()` and `getConsignmentPath()` are absent. Do not offer a complete bridge redemption flow that depends on exporting the burn proof from this engine.

This also affects [WebRGB](/sdk/rgb-sdk#webrgb-integration): a provider over `RgbLibWeb` does not advertise `burnAsset` or `getConsignment`, because WebRGB burn requires proof export.

## Backup and Restore

RGB recovery requires wallet state as well as the mnemonic. Backups restore only with the engine that created them; earlier RLN backups cannot be loaded into `RgbLibWeb`.

### Encrypted Bytes

```typescript
const bytes = await wallet.exportBackup({ password });
await wallet.destroy();

const restored = new UTEXOWallet({
  engine: new RgbLibWeb({
    network: 'signet',
    mnemonic,
    dataDir: 'restored-signet-wallet',
    indexerUrl: 'https://mempool.space/signet/api',
    proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
    evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
  }),
});
await restored.init();
await restored.restoreBackup({ bytes, password });
await restored.unlock();
```

The application stores the encrypted `Uint8Array`. Restore before the first connection. Existing local data is protected unless `overwrite: true` is explicitly supplied.

### VSS

VSS is enabled by default on non-regtest networks, using an identity derived from the mnemonic and the configured server. Set `vssUrl: null` to disable it. Watch-only wallets need an explicit `vss` identity.

| Method | Purpose |
| --- | --- |
| `backupToVss()` | Upload now and return the new server version |
| `getVssBackupInfo()` | Read backup existence, version, pending changes, and the last upload error |
| `restoreFromVss({ overwrite? }?)` | Restore after `init()`, before connecting |

Successful mutations queue VSS uploads, but a successful wallet operation does not guarantee that the upload completed. Use `backupToVss()` for an explicit backup checkpoint and inspect its result.

## Errors and Migration

Use `isEngineError()` from the facade or core to inspect `code` and `operation`. Common failures include `INVALID_CONFIG`, `KEYS_UNAVAILABLE`, `INSUFFICIENT_FUNDS`, `WALLET_INVALID_STATE`, and `UNSUPPORTED_CAPABILITY`.

Import `UTEXOWallet` from `@utexo/rgb-sdk`, construct `RgbLibWeb` from `@utexo/rgb-sdk-web`, and pass `{ engine }`. Remove the previous `password`, `proxyUrl`, Lightning, and RLN lifecycle settings. A backup password is supplied to backup methods, not the engine constructor.

## Lightning Status

Lightning, channels, LSP, and APay are absent from the current Web engine. Experimental Lightning is documented separately as WIP, testing-only, and not recommended for production.
