The Wallet Development Kit (WDK) exposes RGB capabilities through wallet manager and account interfaces. **Use `@utexo/wdk-wallet-rgb` for Node.js on-chain integrations.** Browser applications use `@utexo/rgb-sdk-web`; React Native applications use `@utexo/rgb-sdk-rn`, which supports on-chain operations only.

## WDK Packages

| Package | Purpose | Status |
| --- | --- | --- |
| `@utexo/wdk-wallet-rgb` | On-chain RGB wallets, BFA transfers, burns, and operation recovery | On-chain only |
| `@utexo/wdk-rgb-lightning` | Experimental Lightning channels and payments | WIP, testing-only; not recommended for production |

See the [reference](/sdk/wdk-wallet-rgb) for installation, configuration, and BFA compatibility requirements, or browse the [source repository](https://github.com/UTEXO-Protocol/wdk-wallet-rgb/tree/main).

## When to Use the WDK

Use `@utexo/wdk-wallet-rgb` when:

- You are building a Node.js application with on-chain RGB operations
- Your application uses WDK manager and account abstractions
- You need BFA inventory, on-chain transfers, burns, or operation recovery through a wallet account

Construct `WalletManagerRgb` with the mnemonic, native worker details, fee cap, and transaction approval callback, then call `getAccount()`. With offline startup, call `connect()` before network operations. The SDK uses Electrum; its public signet RGB configuration requires the staging profile. Each wallet needs its own persistent `dataDir` for RGB state and operation journals. Await `shutdown()` before closing or reopening it. The archived `@utexo/rgb-sdk` is not the entry point for new integrations.

## Lightning Status

Lightning remains **WIP**, available only for experimental testing, and **not recommended for production**. The `wdk-rgb-lightning` reference is retained for those tests. Use `wdk-wallet-rgb` for the on-chain integration path. Keep experimental wallet state in a separate directory.
