The Utexo SDK has current Web, React Native, and WDK (Node.js / Bare) packages. `@utexo/rgb-sdk` is archived. Choose the guide for your runtime before copying initialization or transfer code.

<Warning>
  The supported integration path in current packages is **on-chain RGB**. Lightning is **WIP**, for experimental testing only, and **not recommended for production**. In `@utexo/rgb-sdk-rn`, Lightning / RLN is disabled on every network; the current backend is **rgb-lib**.
</Warning>

## Platform API Differences

| Package | Wallet startup | On-chain RGB send |
| --- | --- | --- |
| `@utexo/wdk-wallet-rgb` (Node.js / Bare) | `WalletManagerRgb(mnemonic, config)` + `getAccount()`; `connect()` after offline startup | `sendRgbInvoice({ operationId, invoice, assetId, amount, feeRate })` |
| `@utexo/rgb-sdk` (legacy; source archived) | Construct with a mnemonic and call `initialize()` | `send()` |
| `@utexo/rgb-sdk-rn` | Construct with `{ params, keys }`, then `init()`; network operations connect automatically | `onchainSend()` |
| `@utexo/rgb-sdk-web` | Construct with one parameter object, then call `init()` and `unlock()` | `onchainSend()` |

The Web and React Native packages share on-chain `UTEXOWallet` interfaces but have different backends and lifecycles. `@utexo/wdk-wallet-rgb` uses WDK manager/account types — do not copy `UTEXOWallet` method names into WDK code. The archived Node.js package uses its legacy wallet core; do not substitute `onchainSend()` for `send()` in that package.

## How RGB Transfers Work

1. The receiver generates a blinded or witness RGB invoice.
2. The sender submits the invoice with the platform's on-chain send method.
3. Both wallets refresh their state while the transfer moves through the RGB and Bitcoin confirmation flow.
4. The receiver verifies the asset balance after settlement.

All RGB state is validated client-side. The Bitcoin UTXO anchors the state transition; the transport service delivers consignments but does not replace client-side validation.

## Asset IDs and Amounts

USDT on Bitcoin from the Utexo Mint uses the **BFA** schema. React Native groups assets by schema, with BFA assets in `listAssets().bfa`. The `@utexo/wdk-wallet-rgb` API returns a **flat array**, with BFA entries identified by `schema: 'Bfa'`. Both use `assetId`. `@utexo/rgb-sdk-web` `1.0.0-beta.12` does not list BFA assets yet, so its quickstart uses an NIA test asset.

Amounts are integer base units. Web and React Native invoice APIs use safe JavaScript integers. The WDK API uses decimal strings or `bigint`, including fee rates and UTXO sizes; one displayed unit is `10n ** BigInt(precision)` base units.

```typescript
// React Native: USDT on Bitcoin is a BFA asset
const { bfa } = await senderWallet.listAssets();
const asset = bfa.find((item) => item.ticker === 'USDT');


if (!asset) {
  throw new Error('The sender wallet does not hold USDT on Bitcoin');
}


const assetId = asset.assetId;
const oneDisplayUnit = 10 ** asset.precision;
```

A newly created receiver wallet will not discover an asset it has never received. Obtain the asset ID and precision from the funded sender wallet or another authoritative asset registry. The documentation does not publish a hard-coded test asset ID because no canonical ID is committed in the SDK repositories.

## Lightning Status

These quickstarts cover on-chain transfers. Lightning APIs in the [Web](/sdk/web-sdk#lightning-methods) and [WDK](/sdk/wdk-rgb-lightning) references are **WIP and testing-only**, where available in an experimental build. They are not recommended for production. The current React Native package has Lightning disabled, so its quickstart contains no channel or Lightning payment flow.

## Network Selection

The hosted Web and React Native examples use the `utexo` network profile, which resolves to Utexo's signet infrastructure. The `@utexo/wdk-wallet-rgb` API requires explicit configuration: public Bitcoin `signet`, `mode: 'rgb'`, `profile: 'staging'`, `ssl://stage.electrs-signet.mint.utexo.com:60602`, `rpcs://staging.rgb-proxy.utexo.com/json-rpc`, and the pinned Arbitrum RPC. Its native engine is Electrum-only; it does not accept Esplora indexers. See [WDK configuration](/sdk/wdk-wallet-rgb#configuration). The archived Node.js package uses its package-specific `testnet` profile. Do not reuse a constructor or endpoint configuration across packages without checking the platform implementation.

<Warning>
  Never use mainnet keys or real funds while following a Quickstart. Test and signet assets have no monetary value.
</Warning>

## Common Prerequisites

- A separate sender and receiver wallet for an end-to-end transfer
- Bitcoin test funds for transaction fees
- A funded sender that already holds the RGB asset being transferred
- Secure mnemonic and password storage appropriate for the runtime

The platform guides cover package-specific initialization and method names. End-to-end on-chain settlement time depends on funding, transport availability, and Bitcoin confirmations.
