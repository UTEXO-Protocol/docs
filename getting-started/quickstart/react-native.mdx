Use `UTEXOWallet` from **`@utexo/rgb-sdk`** with **`RgbLibRn` from `@utexo/rgb-sdk-rn`**. The engine uses native rgb-lib and supports on-chain operations only. For other runtimes, see the [Node.js](/getting-started/quickstart/node-js) or [Web](/getting-started/quickstart/web) guide.

## Prerequisites

- React Native with a working iOS or Android native build environment
- Node.js for the development toolchain
- A persistent, writable application directory
- Signet BTC for transaction fees
- A separately initialized sender holding the expected BFA asset

This guide uses public Bitcoin signet and the Utexo staging proxy. Use separate test wallet profiles for the sender and receiver.

## Step 1: Install the SDK

```bash
npm install @utexo/rgb-sdk@latest @utexo/rgb-sdk-core@latest @utexo/rgb-sdk-rn@latest
npm install react-native-fs react-native-get-random-values buffer
cd ios && pod install
```

Load these polyfills in the app entry file before SDK imports:

```javascript
import 'react-native-get-random-values';
import { Buffer } from 'buffer';
globalThis.Buffer ??= Buffer;
```

Rebuild the native application after installation. See the [engine setup](/sdk/react-native-sdk#requirements-and-installation) for details.

## Step 2: Generate and Save Keys

```javascript
import { generateKeys } from '@utexo/rgb-sdk-rn';

const keys = await generateKeys('signet');
await saveMnemonicToSecureStorage(keys.mnemonic);
```

`saveMnemonicToSecureStorage()` represents application-owned secure storage. Generate a mnemonic only for a new wallet; load the saved one on subsequent launches.

## Step 3: Create the Engine and Facade

```javascript
import { UTEXOWallet } from '@utexo/rgb-sdk';
import { RgbLibRn } from '@utexo/rgb-sdk-rn';
import RNFS from 'react-native-fs';

const storageDirPath = `${RNFS.DocumentDirectoryPath}/signet-rgb-receiver`;
await RNFS.mkdir(storageDirPath);

const wallet = new UTEXOWallet({
  engine: new RgbLibRn(
    {
      network: 'signet',
      storageDirPath,
      indexerUrl: 'ssl://stage.electrs-signet.mint.utexo.com:60602',
      proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
      evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
    },
    keys.mnemonic,
  ),
});

await wallet.init();
```

`init()` opens local state. The first network operation connects automatically with the engine's configuration; `wallet.goOnline()` connects explicitly. The EVM RPC is needed to validate BFA mint locks from Arbitrum.

The facade owns the session. Do not initialize or destroy `wallet.engine` separately. The current platform package exports `RgbLibRn`; `UTEXOWallet` comes from the facade package.

## Step 4: Fund the Receiver and Prepare RGB Outputs

```javascript
const address = await wallet.getAddress();
console.log('Signet deposit address:', address);
```

Send signet BTC and wait for confirmations before preparing the outputs:

```javascript
await wallet.syncWallet();
await wallet.createUtxos({ upTo: true, num: 5, size: 1000, feeRate: 2 });
```

Wait for the output transaction to confirm. This guide uses a blinded receive, which needs an existing RGB-capable UTXO. Witness receives instead use a new sender-funded output and do not require this receiver setup.

## Step 5: Resolve the BFA Asset

`senderWallet` is a separate connected wallet with the same network settings, its own mnemonic and directory, and a spendable BFA balance. Obtain `expectedAssetId` from the authoritative deployment metadata.

```javascript
const { bfa } = await senderWallet.listAssets();
const asset = bfa.find((item) => item.assetId === expectedAssetId);
if (!asset) throw new Error('The sender does not hold the expected BFA asset');

const assetId = asset.assetId;
const amount = 10 ** asset.precision;
if (!Number.isSafeInteger(amount)) throw new Error('Amount exceeds the safe integer range');
```

Amounts are integer base units; this sends one displayed unit. A ticker alone does not identify an asset.

## Step 6: Create a Receive Invoice

```javascript
const receive = await wallet.onchainReceive({
  witness: false,
  minConfirmations: 1,
  durationSeconds: 3600,
});
console.log('RGB invoice:', receive.invoice);
```

The receiver has not learned this asset yet, so the invoice omits `assetId` and `amount`. The sender supplies both explicitly.

## Step 7: Send the Asset

```javascript
const result = await senderWallet.onchainSend({
  invoice: receive.invoice,
  assetId,
  amount,
  feeRate: 2,
  minConfirmations: 1,
});
console.log('Transfer transaction:', result.txid);
```

For a witness invoice, also supply `witnessData: { amountSat: 1000 }` to fund the recipient output. Omit it for the blinded invoice above.

## Step 8: Refresh and Verify

```javascript
await senderWallet.refresh();
await wallet.refresh();
console.log('Transfers:', await wallet.listTransfers(assetId));
console.log('Receiver balance:', await wallet.getAssetBalance(assetId));
```

Repeat refreshes on both wallets while consignments arrive and Bitcoin confirmations accumulate. Inspect transfer status until settlement. `refresh()` exposes detailed outcomes; `refreshWallet()` performs the refresh without returning them.

## Step 9: Back Up and Close

```javascript
await wallet.exportBackupToFile({
  filePath: backupFilePath,
  password: backupPassword,
});
await wallet.destroy();
```

The application supplies an absolute backup path outside wallet storage and a securely handled password. A mnemonic alone does not recover RGB state. Restore with `restoreBackupFromFile()` before opening a new wallet instance; see [Backup and Restore](/sdk/react-native-sdk#backup-and-restore).

Close and back up the sender as well. For a temporary pause, `shutdown()` closes the session and `init()` reopens the same instance; `destroy()` permanently closes it.

## Troubleshooting

| Issue | Check |
| --- | --- |
| `UTEXOWallet` is not exported by the platform package | Import it from `@utexo/rgb-sdk` and supply `new RgbLibRn(params, keys)` |
| Native module or version mismatch | Reinstall pods and rebuild the native app |
| Key generation fails | Load random-values and Buffer polyfills before SDK imports |
| Engine contract mismatch | Install compatible facade, engine, and core packages |
| BFA transfer stays pending | Check `evmRpcUrls`, asset ID, proxy compatibility, and refresh results |
| Network operation fails | Check the explicit signet indexer and staging proxy |
| A method is absent on the facade | Use the shared method or supported extension; inspect the [facade reference](/sdk/rgb-sdk#engine-extensions) |

## Lightning Status

Lightning, channels, LSP, and APay are unavailable in the current React Native engine. Experimental Lightning remains WIP, testing-only, and not recommended for production.
