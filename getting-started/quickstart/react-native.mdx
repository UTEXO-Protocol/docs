<Info>
  This guide covers iOS and Android applications. For Node.js, see the [Node.js guide](/getting-started/quickstart/node-js). For browser applications, see the [Web guide](/getting-started/quickstart/web).
</Info>

<Warning>
  The current `@utexo/rgb-sdk-rn` package supports **on-chain RGB only**, through **rgb-lib**. Lightning / RLN is disabled on all networks. Lightning is WIP, for experimental testing only, and is not recommended for production.
</Warning>

## Prerequisites

- React Native with a working iOS or Android native build environment
- Node.js for the development toolchain
- A persistent, writable application directory
- Bitcoin test funds for transaction fees
- A separately initialized sender wallet that already holds the RGB asset for an end-to-end transfer

<Warning>
  This guide uses the `utexo` network profile for Utexo's hosted signet infrastructure. Never use mainnet keys or real funds while following this guide.
</Warning>

## Step 1: Install the SDK

```bash
npm install @utexo/rgb-sdk-rn react-native-fs
```

For iOS, install the native dependencies after adding the package:

```bash
cd ios && pod install
```

The package includes native bindings and is not interchangeable with the Node.js or Web packages.

## Step 2: Generate Wallet Keys

```javascript
import { generateKeys } from '@utexo/rgb-sdk-rn';


const keys = await generateKeys('utexo');
```

Generate keys only for a new wallet. Store the mnemonic in platform-backed secure storage before calling `init()`, and load the same mnemonic on subsequent launches. Do not log it in production or persist it in AsyncStorage.

## Step 3: Initialize the On-chain Wallet

Use the wallet constructor with wallet parameters and keys. Create a persistent directory dedicated to this wallet:

```javascript
import { UTEXOWallet } from '@utexo/rgb-sdk-rn';
import RNFS from 'react-native-fs';

const storageDirPath = `${RNFS.DocumentDirectoryPath}/utexo-onchain-wallet`;
await RNFS.mkdir(storageDirPath);

const wallet = new UTEXOWallet({
  params: {
    storageDirPath,
    network: 'utexo',
  },
  keys: keys.mnemonic,
});

await wallet.init();
```

`init()` opens the local wallet; the first network operation connects automatically using the package's network defaults. For custom endpoints or `regtest`, call `goOnline(params)` after `init()` and before network operations. The RGB proxy must support protocol 1.0.

<Note>
  The previous `new UTEXOWallet(nodeParams, signer)` example selects the disabled RLN backend. The on-chain flow uses `keys`, requires no daemon or peer ports, and needs no separate `unlock()` step. Use a new mnemonic and directory for an on-chain wallet profile; an existing RLN directory or VSS backup cannot be opened as a wallet for the current on-chain implementation.
</Note>

## Step 4: Fund the Wallet

```javascript
const address = await wallet.getAddress();
console.log('Deposit address:', address);
```

Send signet BTC to the address and wait for the required confirmation before creating RGB UTXOs.

## Step 5: Create RGB UTXOs

```javascript
await wallet.syncWallet();
await wallet.createUtxos({ upTo: true, num: 5, size: 1000, feeRate: 2 });
await wallet.syncWallet();
```

`size` is denominated in satoshis.

## Step 6: Resolve the Asset From the Sender

`listAssets()` returns arrays grouped by schema, with the `assetId` field. USDT on Bitcoin from the Utexo Mint uses the **BFA** schema, so it is in `bfa` (from `@utexo/rgb-sdk-rn` `1.0.0-beta.39`). Other test assets are in `nia`, `cfa`, `ifa`, or `uda`.

```javascript
const { bfa } = await senderWallet.listAssets();
const usdt = bfa.find((asset) => asset.ticker === 'USDT');


if (!usdt) {
  throw new Error('The sender wallet does not hold USDT on Bitcoin');
}


const usdtAssetId = usdt.assetId;
const amount = 10 ** usdt.precision; // one displayed unit in base units
```

A new receiver wallet will not list an asset it has never received. Resolve the ID and precision from the funded sender or an authoritative asset registry.

## Step 7: Create a Receive Invoice

Run this on the receiver wallet initialized above:

```javascript
const receiveData = await wallet.onchainReceive({
  witness: false,
  minConfirmations: 1,
  durationSeconds: 3600,
});


console.log('RGB invoice:', receiveData.invoice);
```

This receiver has not received the asset before, so omit `assetId` and `amount` from the invoice. Supply both on the sender in Step 8. For an asset already known to the receiver, they may be included in the invoice. Amounts must be safe integer base units; one displayed unit equals `10 ** precision` base units.

## Step 8: Send From the Funded Wallet

The current React Native API uses `onchainSend()`, not `send()`.

```javascript
const sendResult = await senderWallet.onchainSend({
  invoice: receiveData.invoice,
  assetId: usdtAssetId,
  amount,
  donation: false,
  feeRate: 7,
  minConfirmations: 1,
});


console.log('Transfer transaction:', sendResult.txid);
```

The sender wallet must be a separately initialized `UTEXOWallet` with its own mnemonic and storage directory, sufficient signet BTC, and a spendable asset balance.

## Step 9: Refresh and Verify

```javascript
await senderWallet.refreshWallet();
await wallet.refreshWallet();


const receiverAssets = await wallet.listAssets();
const receivedAsset = receiverAssets.bfa.find(
  (asset) => asset.assetId === usdtAssetId
);


console.log('Receiver asset balance:', receivedAsset?.balance);
```

A transfer can remain pending while its consignment is delivered and its Bitcoin anchor reaches the required confirmation state.

## Step 10: Stop or Dispose of the Wallet

```javascript
await wallet.shutdown(); // preserve data and allow init() on the same instance
// When finished with the instance, release it permanently:
await wallet.dispose();
```

Close the sender session as well. Use encrypted file backups through `createBackup()` and `restoreFromBackup()` to preserve RGB state; the mnemonic alone is not a complete wallet backup. See [Backup and Restore](/sdk/react-native-sdk#backup-and-restore).

## Lightning Status

Lightning, channels, LSP, APay, and RLN VSS are **unavailable in the current React Native package**, including on test networks. There is no Lightning payment step in this quickstart. Any separate experimental Lightning build is WIP, for testing only, and is not recommended for production.

## React Native-Specific Notes

- Store the wallet database in a persistent application document directory, not a cache directory.
- Keep the mnemonic and backup encryption password in platform-backed secure storage.
- Give wallet profiles distinct storage directories; never reuse an RLN directory for the current on-chain wallet.
- Plan for application lifecycle changes. Shut down or dispose of the wallet according to the SDK lifecycle before replacing an instance.
- Network access is required for indexer and RGB transport operations.

## Troubleshooting

| Issue | Likely cause | Check |
| --- | --- | --- |
| Native build fails | Missing platform dependencies | Reinstall pods or rebuild the Android native project |
| `init()` fails | Storage, keys, or native binding problem | Check the absolute directory path, saved mnemonic, and native rebuild |
| `goOnline()` or a network operation fails | Endpoint or proxy incompatibility | Check the network, indexer, and protocol 1.0 RGB proxy |
| RLN backend unavailable | An older RLN constructor is still in use | Use `new UTEXOWallet({ params, keys })` for on-chain operations |
| Asset cannot be found | Wrong response shape or unfunded sender | Read `listAssets().bfa` for Mint USDT and use `assetId` |
| `onchainSend()` fails | Invoice, amount, balance, or transport problem | Confirm the invoice is unexpired and amount is in base units |
