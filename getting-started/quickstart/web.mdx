Use **`UTEXOWallet` from `@utexo/rgb-sdk`** with **`RgbLibWeb` from `@utexo/rgb-sdk-web`**. The engine runs rgb-lib WASM in the browser, stores state in IndexedDB, and supports on-chain RGB including BFA. It has no Lightning backend.

## Prerequisites

- A browser with WebAssembly and IndexedDB
- An ESM bundler serving the engine's WASM asset
- Signet BTC and a separately initialized sender holding the expected BFA asset
- Secure mnemonic storage and a distinct wallet profile for each wallet

This guide uses public Bitcoin signet. Browser indexers must use HTTP(S), so the example uses the public signet Esplora API with the Utexo staging RGB proxy.

## Step 1: Install and Configure the Bundler

```bash
npm install @utexo/rgb-sdk@latest @utexo/rgb-sdk-core@latest @utexo/rgb-sdk-web@latest
```

For Vite:

```typescript
import { defineConfig } from 'vite';

export default defineConfig({
  optimizeDeps: {
    exclude: ['@utexo/rgb-sdk-web', '@utexo/rgb-lib-wasm'],
  },
});
```

The bundler must serve `rgb_lib_wasm_bindings_bg.wasm`; alternatively, set `wasmUrl` on the engine. See [bundler setup](/sdk/web-sdk#installation-and-bundler-setup).

## Step 2: Generate and Save Keys

```javascript
import { generateKeys } from '@utexo/rgb-sdk-web';

const keys = await generateKeys('signet');
await saveMnemonicSecurely(keys.mnemonic);
```

`saveMnemonicSecurely()` is application-owned. Generate keys only once, save them before opening the wallet, and load the saved mnemonic on subsequent launches.

## Step 3: Create the Engine and Facade

```javascript
import { UTEXOWallet } from '@utexo/rgb-sdk';
import { RgbLibWeb } from '@utexo/rgb-sdk-web';

const wallet = new UTEXOWallet({
  engine: new RgbLibWeb({
    network: 'signet',
    mnemonic: keys.mnemonic,
    dataDir: 'signet-rgb-receiver',
    indexerUrl: 'https://mempool.space/signet/api',
    proxyEndpoint: 'rpcs://staging.rgb-proxy.utexo.com/json-rpc',
    evmRpcUrls: { '42161': 'https://arb1.arbitrum.io/rpc' },
  }),
});

await wallet.init();
```

`init()` loads WASM and opens local wallet state. Network operations connect automatically; `unlock(params)` or `goOnline(params)` connects explicitly. Configure the sender with the same network services and its own keys and IndexedDB profile.

The `dataDir` value is an IndexedDB prefix, not a filesystem path. Use it consistently when reopening. The EVM RPC validates BFA mint locks on Arbitrum. Browser access to all configured services requires compatible CORS settings.

## Step 4: Fund and Prepare the Receiver

```javascript
console.log('Signet deposit address:', await wallet.getAddress());
```

Fund the address with signet BTC and wait for confirmations. Then prepare outputs for a blinded receive:

```javascript
await wallet.syncWallet();
await wallet.createUtxos({ upTo: true, num: 5, size: 1000, feeRate: 2 });
```

Wait for the output transaction to confirm. A witness receive does not need a receiver UTXO; its sender must instead provide `witnessData.amountSat`.

## Step 5: Select the BFA Asset

The initialized `senderWallet` must hold the expected BFA asset and BTC for fees. Get `expectedAssetId` from authoritative deployment metadata.

```javascript
const { bfa } = await senderWallet.listAssets();
const asset = bfa.find((item) => item.assetId === expectedAssetId);
if (!asset) throw new Error('The sender does not hold the expected BFA asset');

const assetId = asset.assetId;
const amount = 10 ** asset.precision;
if (!Number.isSafeInteger(amount)) throw new Error('Amount exceeds the safe integer range');
```

The current Web engine lists BFA assets in `listAssets().bfa`. Amounts use safe integer base units; this example sends one displayed unit.

## Step 6: Create an Invoice and Send

```javascript
const receive = await wallet.onchainReceive({
  witness: false,
  minConfirmations: 1,
  durationSeconds: 3600,
});

const result = await senderWallet.onchainSend({
  invoice: receive.invoice,
  assetId,
  amount,
  feeRate: 2,
  minConfirmations: 1,
});
console.log('Transfer transaction:', result.txid);
```

The receive invoice omits an asset ID because the receiver has not learned the asset yet. The sender supplies it and the amount explicitly. Use a separate wallet instance for each party.

## Step 7: Refresh Until Settlement

```javascript
await senderWallet.refresh();
await wallet.refresh();
console.log('Receiver transfers:', await wallet.listTransfers(assetId));
console.log('Receiver balance:', await wallet.getAssetBalance(assetId));
```

Repeat refreshes on both wallets and inspect transfer status. One refresh does not guarantee that consignments and Bitcoin confirmations have arrived.

## Step 8: Back Up and Close

```javascript
const backupBytes = await wallet.exportBackup({ password: backupPassword });
await saveEncryptedBackup(backupBytes);
await wallet.destroy();
```

The application supplies `backupPassword` and persists the encrypted bytes with `saveEncryptedBackup()`. Back up and close the sender too. A mnemonic alone does not recover RGB state.

For restore, create a new engine with the same keys and a separate `dataDir`, call `init()`, then `restoreBackup({ bytes, password })` **before connecting**. VSS backups are also available; see [Backup and Restore](/sdk/web-sdk#backup-and-restore).

## BFA Burns and Lightning

The Web engine supports local burns but does not export consignments. A bridge redemption that requires a burn proof cannot be completed through this engine alone. WebRGB providers over it therefore do not advertise `burnAsset` or `getConsignment`.

Lightning, channels, LSP, and APay are absent. Separate experimental Lightning integrations remain WIP, testing-only, and not recommended for production.

## Troubleshooting

| Issue | Check |
| --- | --- |
| `UTEXOWallet` import fails | Import it from `@utexo/rgb-sdk`, and `RgbLibWeb` from the platform package |
| WASM fails to load | Check the emitted asset URL, bundler configuration, and optional `wasmUrl` |
| Indexer rejected | Use HTTP(S) Esplora; browser wallets cannot use Electrum |
| BFA transfer pending | Check the asset ID, `evmRpcUrls`, proxy, and refresh results |
| Restore rejected | Restore after `init()` but before any online call, into a fresh profile |
| Network requests fail | Check CORS and endpoint availability |
| Engine contract mismatch | Install compatible facade, engine, and core packages |
